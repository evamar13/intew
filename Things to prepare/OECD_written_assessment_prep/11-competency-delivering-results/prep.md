# Competency: Delivering Results

## What It Means At OECD

This competency is about producing quality outputs on time, using resources well, solving problems, and meeting stakeholder needs with professionalism.

For a written assessment, this competency is visible not only in what you say, but in how your answer is built.

In the OECD Maki activity library, this likely overlaps with explicit labels such as:

- Achieve Results
- task prioritisation
- work planning

## How Assessors Will Probably Read This

They may ask:

- Is the response structured?
- Is it relevant?
- Is it actionable?
- Does it prioritise?
- Does it move from analysis to recommendation?
- Does it show a practical mindset?

## What To Show In Your Writing

- focus on outputs that can realistically be delivered
- prioritise instead of listing everything
- propose phased implementation when appropriate
- show awareness of time, effort, and resource constraints
- make the recommendation usable

## Practical Behaviors You Can Signal

- setting priorities
- sequencing work
- defining quick wins
- identifying what can be piloted first
- aiming for high-quality, realistic outputs

## Example Strong Moves

- recommend a pilot before full rollout
- distinguish core KPIs from optional exploratory metrics
- propose a small reporting cadence instead of a complex framework
- identify immediate and medium-term actions

## Useful Phrases

- "I would start with a limited pilot focused on high-value outputs."
- "The first priority is to establish a defensible baseline before expanding coverage."
- "This approach balances usefulness, feasibility, and methodological caution."
- "This should be implemented in phases, beginning with the highest-priority outputs and stakeholders."

## What Weak Answers Look Like

- ambitious proposals with no implementation logic
- too many priorities
- no sense of sequencing
- no recommendation, only description
- theoretical discussion without action

## Your Output Should Feel Like This

- clear
- organised
- efficient
- practical
- calm
- accountable

## Self-Check

- Did I prioritise clearly?
- Did I recommend something feasible?
- Did I include implementation logic?
- Did my answer feel usable, not just intelligent?
